## Exact failure and independent reproduction

The response uses VOTable BINARY and declares signed-64-bit source IDs with a
null sentinel of -9223372036854775808. The installed Astropy source implements
`fast_binparse_long` with an int64_t data value but a **C long null_value argument**.
On this Windows runtime C long is four bytes, whereas the declared null sentinel
requires eight. Python-to-C conversion of the sentinel fails before source data
can be compared. A separate synthetic call with the same valid 64-bit source ID
and null checking disabled succeeds; passing the declared sentinel reproduces
the OverflowError. This isolates the null-argument width, not loss of source-ID
precision in the actual binary value. No environment/library patch was made.

Primary local implementation evidence:
`dyson-revet/.venv/Lib/site-packages/astropy/io/votable/converters.py`, Long.binparse,
and `astropy/io/votable/src/fast_converters.pyx`, fast_binparse_long.
The diagnostic does not assert whether this issue is already known upstream.

The [dedicated read-only verifier](scripts/verify_m1c_failure.py) checks manifest,
query, outcome and raw-response hashes; reproduces the same parser error; verifies
the synthetic C-width failure and absence of either later request directory.

## Smallest possible next repair, not performed or authorized by this result

decode the explicitly declared eight scalar BINARY columns in big-endian order,
using signed int64 for IDs, float64 for five astrometric fields and float32 for G
and RUWE. Require exact fixed row length (56 bytes), reject arrays/BINARY2/external
streams/unknown datatypes, validate base64 and no partial row, and apply the
declared integer-null sentinel and floating NaN masks without dropping either.
Retain the original XML and units; do not delete a null declaration to make an
error disappear. Independently verify this small decoder on synthetic positive,
negative/extreme int64, null, NaN, truncated and wrong-schema cases, ideally against
a second standards-conforming implementation, before processing retained rows.

Then apply the **unchanged** M1c eight-column ID/mask/unit/numerical parity contract
to the retained first-field ESA and ARI responses. A failed comparison remains
STOP. No new requests are needed to establish whether that offline repair works.
Even if parity passes, any later two-field requests would need a separately
authorized continuation preserving the original stop and one-request limits.
