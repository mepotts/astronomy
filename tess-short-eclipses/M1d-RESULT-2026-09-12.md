# M1d: stopped before numerical parity

The independently reviewed, frozen run at commit `ed733ef` returned
`STOP_M1D: STOP_TABLE_STRUCTURE`. No catalogue rows were decoded or compared;
there were zero network requests and no pixel measurements. Runtime acceptance
receipt: 0.016 seconds in the worker, peak working set 102,002,688 bytes.

The retained ARI XML has one results TABLE but **two RESOURCE siblings**. Its
second RESOURCE is table-free service metadata. Our preflight inspected the
field layout but incorrectly assumed one RESOURCE in the complete document.
Both the author's and reviewer's synthetic fixtures omitted this case. This is
our strict-profile error, not evidence of inconsistent Gaia data or an invalid
archive response. The original source, protocol, manifest and result remain
unchanged. [Recorded outcome](out/m1d-result.json).

A separate M1d2 adapter will verify the complete metadata structure, ignore only
the documented table-free service descriptor in memory, and retain the same
decoder, masks, IDs, units and parity thresholds. It must not dereference a
descriptor URL or silently discard any extra scientific table/status. No new
request is needed. A successful software amendment would not establish source
localization or authorize an unknown search.
