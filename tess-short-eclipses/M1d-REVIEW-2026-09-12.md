### Normative encoding and mask rules

VOTable 1.4 sections 5.3–5.5 and 6 specify row-ordered binary cells, big-endian
signed 64-bit `long`, and IEEE 32/64-bit floating types. BINARY has no separate
row mask; declared integer null sentinels must be respected. BINARY2 prepends
`ceil(number_of_fields/8)` null-flag bytes per row, first column at the most
significant bit. NaN may be treated as null; implementations need not preserve
that distinction. Infinity is not NaN. An empty TABLEDATA TD represents null,
but TABLEDATA is not the actual retained ESA encoding. These are distinct
serialization contracts, not interchangeable layouts.
[IVOA VOTable 1.4 Recommendation](https://www.ivoa.net/documents/VOTable/20191021/REC-VOTable-1.4-20191021.html).

For this exact ARI schema the fixed row length is 56 bytes, with offsets
0, 8, 16, 24, 32, 40, 48 and 52. The narrow repair should leave the existing
strict ESA/Astropy BINARY2 path intact and implement only ARI BINARY. Rejecting
other valid VOTable profiles is an intentional scope limit, not a declaration
that those files violate the standard. A broader BINARY2 implementation would
require its own mask-byte tests and an explicit scope decision before execution.

### Recommended independent oracle and adversarial checks

Use two genuinely different low-level unpacking routes on **synthetic** fixtures:
stdlib `struct.Struct('>q5d2f')` and a NumPy structured dtype with explicit
`>i8`, five `>f8`, two `>f4`, `align=False`, and verified itemsize 56. Do not
construct one homogeneous array from mixed rows: that can silently convert IDs
to floats. Compare integer values exactly, optional masks exactly and finite
floating values at their declared storage precision. Neither small implementation
should be called a fully general or independently certified VOTable reader.

Recommended fixtures before source/protocol freeze:

- Adjacent integers above 2^53, negative one, signed64 minimum/maximum and the
  declared sentinel. Low-level signed decoding must be exact; subsequent Gaia
  positive/unmasked-ID validation must reject inappropriate values explicitly.
- Multiple positive/negative NaN bit patterns independently in each floating
  field, signed zeros, subnormals, infinities and byte-order reversal. Mask only
  NaNs under the declared policy: masking every nonfinite number would conceal
  infinities from the unchanged finite-value gate.
- Truncated/trailing row bytes, empty streams, malformed base64/padding, and
  unexpected stream children or external/compressed streams. Count rows from the
  exact fixed-width payload, never silently discard a partial final row.
- Wrong/reordered/missing/duplicate FIELD names or types; arrays and extended
  datatypes; duplicate tables/streams; BINARY2 presented to the BINARY-only decoder;
  missing/invalid/out-of-range null sentinel and unexpected null conventions.
- An OK QUERY_STATUS followed by ERROR/OVERFLOW, missing status, wrong namespace,
  conflicting FIELD NAME/ID, wrong/missing/scaled units and duplicate Gaia IDs.
- Mask mismatches and every unchanged M1c parity boundary. Preserve optional
  missing values rather than filling them with zeros. Keep scientific acceptance
  separate from low-level bit decoding and retain all original M1c failures.

**Execution boundary:** no real ARI numeric decoding/parity should occur until
the new protocol, implementation, independent synthetic checks and hashes are
frozen. A successful offline software repair alone would not authorize either
missing-field request, prove source localization, or create a discovery.
