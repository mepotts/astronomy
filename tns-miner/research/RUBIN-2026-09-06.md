# Rubin public-control follow-up - parked with a narrower blocker

**No complete CV search earned.** Thirteen finite public-source/control requests
and two explicitly corrected cone requests were executed. All raw results,
including failures, are retained in [the response bundle](rubin-controls-20260906.zip).
It also contains all three September 5 input bundles, with their original
manifest hashes unchanged. [Cold-replay audit](rubin-control-audit-20260906.json).

For the documented rich public control `313761043604045880`, a fresh all-column
Fink query returns exactly the same 693 detection IDs and 580 forced IDs. The
retained ALeRCE table has 742/589. Exact integer joins now identify both the 49
extra detections and nine extra forced measurements; these are not floating-point
ID losses. The nine span MJD(TAI) 61090.069497-61098.056004, overlapping the
detection-history gap. Shared detection fluxes still agree exactly.

The inspected [Fink sources implementation](https://github.com/astrolabsoftware/fink-object-api/blob/main/apps/routes/v1/lsst/sources/utils.py)
reads its static source table and exposes no user pagination parameter here.
Requesting all columns does not recover the missing data. This rules out our
column projection as the cause; it does NOT prove what happened in broker
ingestion, history reconstruction or storage. Those upstream causes remain
unresolved and no particular outage or quality filter is asserted.

A timestamp-key lookup returned zero rows for BOTH the earliest missing detection
and an independently known-present control. The implementation constructs a key
from a timestamp string, and JSON time rounding is a plausible mechanism, not a
proven root cause. **Do not use this endpoint's empty response as absence evidence.**
Use full-object retrieval and exact measurement IDs for local matching.

The two new fixed CVs, Z Cha and HL CMa, both return zero ALeRCE objects within
3 arcsec. Fink initially returns HTTP 400 because date filtering requires
`f:firstDiaSourceMjdTaiFink` in the requested columns. The two corrected requests
return HTTP 200 with zero rows. Errors were not counted as empty histories.
Together with September 5's VW Hyi/OY Car probes, four named CVs lack positive
public-control coverage at these coordinates. This is not an all-sky completeness
measurement, nor evidence of astrophysical quiescence or no Rubin visits.

**Decision:** park this CV-history pilot. Do not build a population enumerator
around incomplete histories or keep polling the same examples. Reopen on a public
CV with documented usable coverage AND an understood history/quality contract,
or an independently validated complete time-window product. No unknown-source
queries or outward broker messages were sent.
