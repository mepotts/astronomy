SOAK TEST -- 5 identical requests at batch 10 ------------------
  seconds: [42.3, 72.2, 27.2, 22.7, 29.3]
  median 29.3 s, min 22.7, max 72.2, spread 3.2x
  trend across the run: -7.55 s per request (R^2 0.35)
  -> not a clean monotone rise: the spread is archive LOAD, not a rate
     limit aimed at us.  The VARIANCE is the finding -- any single-call
     timing is worthless for planning, which is why the projection below
     is a band and why the harness is resumable.

TWO TRANSPORT MODELS, both fitted to the same calls --------------------
  A transport-limited  t = 2.3 s + bytes / 1.8 KiB/s      (R^2 0.934)
  B per-source work    t = 6.0 s + 3.86 s per source      (R^2 0.917)
  fitted on 6 sweep calls spanning 2.8-164.2 s and 8-278 KiB
  probe payload: 7.5 KiB/source (DR3 epoch photometry)
  The two fit the SAME data about equally well because bytes and sources are
  collinear in the probe.  They disagree about DR4 only because DR4's payload
  per source is ~7x bigger -- exactly the extrapolation that cannot be tested
  until the data exists.  Hence a band, not a number.

HEADLINE ---------------------------------------------------------------
  MEASURED today, end to end on real epoch astrometry: the single-star-fit
  half of the loop runs at 101,149 sources/hour (0.036 s/source).
  It is NOT the bottleneck and never will be.
  MEASURED today on the live DataLink service: 3.9 s per source at 8 KiB/source, 2.3-6.0 s per request.

  PROJECTED day-one throughput at batch 20, undegraded:
    model B (per-source work): 854 sources/hour -> 983 rows in 1.2 h
    model A (transport):       125 sources/hour -> 983 rows in 7.9 h
  => THE BAND: 125-854 sources/hour, i.e. the 983-row queue in 1.2-7.9 h.
  At a 10x-degraded archive (release-day branch, model A): 78 h -- the only
  branch measured that does NOT fit inside the runbook's 72 h.

  CONSEQUENCE for the runbook, and it is the actionable one: the queue is
  RANKED and the harness consumes it in rank order, so a slow archive costs
  DEPTH, not the headline -- BH1, BH2 and the spurious poster child are
  adjudicated in the first minutes under every branch.  The failure mode to
  plan for is running out of hours, not running out of throughput, and the
  mitigation is already in the harness: it is resumable, so 72 h is a
  checkpoint, not a deadline.

  ASSUMPTIONS carried, not hidden:
    (i) DR4 epoch astrometry is served by the same DataLink service at a cost
        between 'same per source' (B) and 'same per byte' (A).
   (ii) release day is busier than a quiet Friday -- hence the degrade column.
  (iii) the probe used DR3 EPOCH_PHOTOMETRY because DR4 epoch astrometry does
        not exist yet.  RE-RUN THIS SCRIPT ON 2026-12-02 with the real
        retrieval type BEFORE committing to a batch size: it takes ~6 minutes
        and replaces every projected number with a measured one.
